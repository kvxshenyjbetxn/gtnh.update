# GTNH Updater

Окрема десктопна програма для підготовки оновлень **GregTech: New Horizons** зі збереженням ваших даних на клієнті та сервері.

## Можливості

- Каталог офіційних релізів GTNH із вибором варіанта Java та завантаженням прямо у програмі.
- Одночасне завантаження кількох архівів клієнта й сервера, різних версій і варіантів Java.
- Прогрес, скасування й повторна спроба — у рядку відповідного файлу. Клієнтські завантаження видно лише на вкладці клієнта, серверні — на серверній; перемикання вкладок їх не зупиняє.
- Архіви зберігаються в `downloads` у папці конфігурації користувача. Незавершені `.part` прибираються після скасування або помилки; готовий `.zip` залишається після встановлення, його можна видалити кнопкою «Видалити архів» поруч.
- Встановлення завантаженої клієнтської збірки в новий інстанс Prism з перенесенням увімкнених правил. Папки об’єднуються без видалення нових файлів; заміни показуються до підтвердження, конфлікти «Запитувати» потребують вибору.
- Оновлення локальної копії папки сервера на місці за офіційною інструкцією GTNH: попередні файли потрапляють у резервну копію поруч із сервером, а перед підтвердженням показується план.
- Безпечне розпакування без символічних посилань і виходу за каталог, перевірка вільного місця та окрема тимчасова підготовка. Для клієнта стару збірку й наявні папки призначення програма не перезаписує.
- Автоматичне збереження налаштувань, зокрема теми, мови, папки Prism, правил перенесення та перемикача стабільних і beta/RC версій.
- Збереження статистики гри зі старого `instance.cfg` та синхронізація назви нового інстансу у Prism з назвою, введеною перед встановленням. Інші параметри нової збірки не замінюються старими.
- Правила перенесення для клієнта: стандартні за вікі та власні.
- «Мої моди» для клієнта й сервера: додавайте власні `.jar`-моди — вони замінюють такий самий мод у новій збірці — або прибирайте непотрібні. Моди розпізнаються за внутрішнім ідентифікатором, тому правила працюють і тоді, коли змінюється версія мода. Якщо в підсумку лишаються два файли одного мода, програма попереджає про це.
- Для сервера — правила «Перенести зі старого сервера» для власних конфігів і файлів.
- «Перейменування файлів» для клієнта: наприклад, `ru_RU.lang` у новій збірці автоматично стає `en_US.lang` у тій самій папці. Якщо файл із новою назвою вже є, його буде замінено; якщо вихідного файлу в збірці немає, правило пропускається.
- Вибір файлів і папок через системний діалог, налаштування дій при конфліктах.
- Українська й англійська мови, світла та чорна AMOLED теми.

## Завантаження й запуск програми

Опубліковані збірки доступні в [GitHub Releases](https://github.com/kvxshenyjbetxn/gtnh.update/releases/latest). Остання версія — **0.3.0** (Windows). Для macOS поки доступна лише версія **0.1.1**.

### Windows (x64)

1. Завантажте `GTNH-Updater_0.3.0_windows_x64_portable.exe` з релізу 0.3.0.
2. Запустіть його — встановлення не потрібне. Якщо Windows показує попередження SmartScreen, натисніть **Докладніше → Усе одно запустити**.
3. Потрібен Microsoft Edge WebView2 Runtime — у Windows 10 і 11 він зазвичай уже є.

### macOS (Apple Silicon, arm64)

1. Завантажте `GTNH-Updater_0.1.1_macos_arm64_portable.zip` і розпакуйте його.
2. Запустіть `GTNH Updater.app` із розпакованої папки або перемістіть у `Applications`. Інсталятор, Node.js і Rust для запуску не потрібні.
3. Збірка не має підпису Developer ID та нотаризації Apple. Якщо macOS блокує запуск, перевірте джерело завантаження й контрольну суму, а потім дозвольте відкриття через **Системні параметри → Приватність і безпека → Відкрити однаково**, якщо цей пункт доступний. Не вимикайте Gatekeeper глобально.

Архів призначений для **Apple Silicon**, не для Intel Mac. «Портативна» означає запуск `.app` без інсталятора, а не збереження всіх даних поряд із нею: налаштування й завантаження розміщуються в каталозі конфігурації користувача. Його можна відкрити з налаштувань програми. Поряд із ZIP у релізі є `SHA256SUMS.txt` для перевірки цілісності.

Готової збірки для Linux поки немає.

## Оновлення збірки GTNH

Спочатку в **Налаштуваннях → Папка інстансів Prism** один раз оберіть папку `instances` — налаштування збережуться автоматично. Вона буде початковим розташуванням для вибору старого інстансу й місцем встановлення нового. Власний шлях підтримує portable Prism. Якщо папку Prism не задано або вона недоступна, майстер відкриває налаштування для її вибору.

Оновлення відбувається на одній сторінці з чотирма послідовними секціями. **«Продовжити»** згортає поточну секцію в короткий підсумок і відкриває наступну; натискання на заголовок завершеного етапу повертає до редагування.

1. **Стара збірка / Папка сервера.** Для клієнта оберіть старий інстанс Prism / `.minecraft` — його програма не змінює. Для сервера оберіть локальну копію папки сервера, яку потрібно оновити.
2. **Нова збірка.** Завантажте реліз із каталогу, оберіть Java й після завершення натисніть **«Обрати цю збірку»**. Або оберіть **«Збірка вже завантажена» → «Обрати ZIP» / «Обрати папку»** — відкриється стандартне системне вікно. Власного файлового браузера немає. Прогрес завантаження не губиться при згортанні секції.
   Для клієнта потрібен повний архів/інстанс Prism із `instance.cfg` та `mmc-pack.json`, для сервера — серверна збірка (папка або архів). Вибраний користувачем ZIP чи папка **ніколи не видаляється й не змінюється**. Якщо нова збірка має нестандартний `instance.cfg` з іменованими секціями, але без `ConfigVersion`, спочатку відкрийте й збережіть її у Prism: встановлення такого неоднозначного формату блокується. З аналогічного старого файлу статистика не переноситься.
3. **Що перенести / Що зміниться.** Для клієнта перегляньте кількість увімкнених правил і за потреби змініть вибір в **«Усі правила та власні файли»**; зміни зберігаються автоматично. Для сервера тут коротко описано, що буде замінено, а що залишиться без змін, і можна додати правила **«Перенести зі старого сервера»** для власних файлів (наприклад, `config/serverutilities.cfg`; шляхи вважаються відносно папки сервера).
   **«Мої моди»** (клієнт і сервер): **«Додати мод»** — оберіть один чи кілька `.jar`-файлів з будь-якого місця, і вони замінять такий самий мод у новій збірці; новіша версія вашого мода замінює попереднє правило. **«Прибрати мод»** — оберіть `.jar` (зазвичай зі старої папки `mods`), і мод буде прибрано з нової збірки, навіть якщо версія в назві файлу інша. Правила застосовуються автоматично щоразу, їх можна вмикати, вимикати й видаляти. Якщо ідентифікатор мода не знайдено, пошук іде за назвою файлу — це менш надійно.
4. **Перевірка та встановлення.** Для клієнта перевірте збірки, правила, моди та назву **нового, ще неіснуючого** інстансу. Введена назва також записується в `instance.cfg` і відображається у Prism; награний час та час останнього запуску успадковуються зі старого інстансу, якщо знайдено коректні значення. Папка Prism береться з налаштувань без повторного вибору в майстрі. Натисніть **«Підготувати й перевірити»**, перегляньте фактичний список файлів і папок (включно з порожніми), вирішіть конфлікти й окремо підтвердьте перенесення. План можна скасувати; під час розпакування й копіювання потрібно дочекатися завершення. Поки операція активна, змінювати збірки й правила не можна; налаштування можна переглянути без втрати прогресу.

Після завершення запустіть новий інстанс у Prism (перезапустіть Prism, якщо інстанс не з’явився). Закрийте Minecraft перед копіюванням і зробіть резервну копію світу. Ігрові файли клієнта копіюються **лише за зазначеними правилами** (статистика Prism переноситься окремо). Не переносіть старі `mods` або весь `config` без перевірки сумісності.

### Оновлення сервера

Сервер оновлюється на місці, за офіційною інструкцією GTNH. Працюйте з локальною копією папки сервера на своєму комп’ютері:

1. Оберіть папку сервера.
2. Оберіть нову серверну збірку: завантажте її з каталогу або виберіть уже наявний архів чи папку.
3. Перегляньте план: що буде замінено, що додано, які моди додаються чи прибираються (з попередженням про дублікати та моди, яких не знайдено), які власні файли переносяться (за потреби оберіть дію для наявних), чи зміняться скрипти запуску (старий і новий текст видно поруч) і чи потрібна інша версія Java.
4. Підтвердіть кнопкою **«Оновити сервер»**.

Що відбувається: `config`, `libraries`, `mods`, `resources`, `scripts` і файли запуску (скрипти `startserver`, jar-файли, `java9args.txt`) переносяться в резервну копію, а на їхнє місце ставляться нові. Ідентифікатор карти JourneyMap (`config/JourneyMapServer`) зберігається. Світ, `server.properties`, списки whitelist / ops / banned, `eula.txt`, `serverutilities` та інші файли не змінюються.

Резервна копія лежить поруч із папкою сервера: `<назва папки сервера>.gtnh-backup`. Зберігається лише остання — наступне оновлення замінює попередню. Власні конфіги переносяться правилами «Перенести зі старого сервера», а власні моди — через «Мої моди»; усе інше можна повернути вручну з резервної копії. Налаштування пам’яті (`-Xmx`) у скриптах запуску також можуть потребувати повторного налаштування.

Перед оновленням зупиніть сервер і зробіть окрему копію світу. Якщо оновлення було перервано, наступного разу програма сама поверне попередній стан або завершить його та повідомить про це. Коли все готово, завантажте оновлену папку сервера на хостинг самостійно.

Java не встановлюється, Minecraft/сервер не запускаються, EULA не приймається автоматично. Перенесення чи оновлення не замінює запуск світу в проміжних гілках GTNH. Стан завантажень зберігається лише у поточному сеансі програми. Після перезапуску наявний ZIP можна вибрати через «Обрати ZIP» — повторне завантаження не потрібне.

Автоматичної перевірки оновлень GTNH та самооновлення програми наразі немає: потрібну збірку GTNH обирають у каталозі, а нову версію GTNH Updater завантажують із GitHub Releases.

Цільові платформи — **macOS, Windows і Linux**.

## Розробка й перевірки

Інтерфейс написано на [GPUI](https://www.gpui.rs/) (Rust); Node.js, npm і WebView2 не потрібні. Потрібен Rust версії не нижче 1.95. На Windows — toolchain MSVC (`x86_64-pc-windows-msvc`) з C++ Build Tools та Windows SDK. На Linux потрібні системні пакети (Ubuntu/Debian):

```sh
sudo apt-get install -y pkg-config libxkbcommon-dev libxkbcommon-x11-dev libwayland-dev libxcb1-dev libfontconfig-dev libfreetype-dev
```

Запуск у режимі розробки:

```sh
cargo run -p gtnh-updater
```

Перевірки, які також запускає `.github/workflows/check.yml` на macOS, Linux і Windows:

```sh
cargo fmt --all -- --check
cargo test --workspace --locked
cargo clippy --workspace --all-targets --locked -- -D warnings
```

### Релізна збірка

```sh
cargo build --release -p gtnh-updater
```

Результат — `target/release/gtnh-updater` (`targetelease\gtnh-updater.exe` на Windows). Це непідписаний виконуваний файл без інсталятора; Rust на комп'ютері користувача не потрібен. Пакет macOS `.app` поки не створюється. Налаштування та завантаження зберігаються в каталозі конфігурації користувача, а не біля виконуваного файлу. Збірка сама по собі не є опублікованим релізом.

Для Linux потрібне відповідне середовище та формат пакування. Правила підвищення й синхронізації версій описано в `AGENTS.md`.

Незалежний проєкт, не офіційний продукт команди GTNH. Перед оновленням зберігайте резервну копію світу.
